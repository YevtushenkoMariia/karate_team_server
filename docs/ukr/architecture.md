# Архітектура

Сервер побудований як **модульний моноліт**: один процес Fastify для розгортання
та одна база даних PostgreSQL, поділені на модулі з чіткими межами.

## Структура

```
src/
  index.ts          точка входу: завантаження конфігурації та запуск сервера
  app.ts            корінь композиції: створює модулі та з'єднує залежності
  config.ts         типізована й перевірена конфігурація середовища
  shared/           спільне ядро (без бізнес-логіки)
    db.ts             фабрика Prisma Client
    errors.ts         підкласи AppError, зокрема NotFound і Forbidden
    events.ts         внутрішній EventBus для подій між модулями
    http/auth.ts      хуки authenticate / authorize / requireSelf
    http/error-handler.ts   єдине перетворення помилок на HTTP-відповіді
  modules/
    identity/       облікові записи, реєстрація та вхід (таблиця: users)
    members/        профілі спортсменів і тренерів (sportsmen, coaches, coach_sportsman)
    groups/         тренувальні групи та учасники (groups, users_groups)
    locations/      міста, клуби та країни (cities, clubs, countries)
```

Усередині модуля:

| Файл                  | Відповідальність                                      |
|-----------------------|-------------------------------------------------------|
| `index.ts`            | **Публічний API** — єдиний файл для імпорту іншими модулями |
| `<m>.module.ts`       | Створює модуль із залежностей і оголошує маршрути     |
| `<m>.api.ts`          | Інтерфейс (фасад), доступний іншим модулям             |
| `*.controller.ts`     | Лише обробка HTTP-запитів і відповідей                 |
| `*.service.ts`        | Сценарії використання та бізнес-правила               |
| `*.repository.ts`     | Доступ до **власних** таблиць модуля                   |
| `*.schemas.ts`        | Схеми запитів TypeBox (валідація та OpenAPI)            |

## Правила

1. **Імпортуйте лише через `index.ts`.** Наприклад, `groups` використовує
   `IdentityApi` з `../identity`, а не `../identity/users.repository`.
2. **Модуль запитує лише власні таблиці.** Дані іншого модуля отримуйте через
   його API (наприклад, авторів груп — через `identity.findUsersByIds`).
3. **`shared/` не залежить від `modules/`.**
4. **Залежності передаються через конструктор** `create<Module>Module(deps)`;
   singleton-и під час імпорту не створюються, тому сервіси можна тестувати з
   підставними залежностями.
5. **Помилки потрібно кидати, а не надсилати напряму.** Сервіси кидають
   підкласи `AppError`, а глобальний обробник формує відповідь
   (`{ statusCode, error, message }`).
6. **Побічні ефекти між модулями проходять через події.** Наприклад, `identity`
   публікує `UserRegistered`; `members` підписується на подію та створює запис
   тренера або спортсмена. `identity` не знає про існування `members`.

Правила 1–3 автоматично перевіряє команда `npm run check:boundaries`.
Додаючи таблицю, зареєструйте її власника в `scripts/check-boundaries.mjs`.

## Транзакції між модулями

Для атомарних операцій у кількох репозиторіях використовуйте
`runInTransaction(db, async (tx) => { ... })` зі `shared`. Створюйте кожен
репозиторій, який бере участь у транзакції, з `tx`, а не з кореневим `db`.
Конструктори репозиторіїв приймають спільний тип `DbClient`, тож їм можна
передавати транзакційний клієнт. Unit of Work для `updateProfile` прив’язує
репозиторії identity, locations і members до однієї транзакції.

## Залежності між модулями

```
identity  <──  members  ──>  locations
   ^
   └────────  groups
members ··(подія UserRegistered)··> identity
```

Циклів немає: `identity` і `locations` ні від чого не залежать.

## Додавання модуля (наприклад, `training`)

1. Створіть `src/modules/training/` з `training.module.ts`, `index.ts` та шарами.
2. Зареєструйте його таблиці в `TABLE_OWNERS` у
   `scripts/check-boundaries.mjs`.
3. Додайте модуль у `app.ts`, передаючи лише потрібні йому API.

## Перехід до окремих сервісів

Кожен модуль уже взаємодіє з іншими через інтерфейс та шину подій. Щоб винести
модуль в окремий сервіс, достатньо замінити реалізацію його `*Api` на HTTP/RPC
клієнт, а `EventBus` — на брокер повідомлень; код викликів змінювати не потрібно.
